          TSITA GEST × BSCA Bank · Guide interactif

          Chaque demande mérite une réponse claire.

          TSITA GEST est la plateforme de gestion des réclamations de BSCA Bank, Banque Sino-Congolaise pour l'Afrique. Elle relie le dépôt multicanal, l'instruction par les équipes, la solution, la réponse au client et la mesure des causes récurrentes — avec une trace complète de chaque décision.

          Guide de démonstration. Toutes les données affichées (références, clients, montants, indicateurs) sont fictives. Les seuils de délai (accusé de réception en 10 jours ouvrés, réponse en 45 jours calendaires) sont des valeurs de démonstration à valider par la conformité BSCA avant toute mise en production.

          Statuts et transitions

          Cycle de vie d'un dossier

          Onze statuts de traitement et leurs transitions autorisées par le serveur. Chaque transition est horodatée, motivée et journalisée. Survolez ou sélectionnez un statut pour voir qui peut agir et ce que voit le client.

          Transition vers l'avant Retour arrière Statut sélectionné Statut suivant possible

          La décision de fond est une dimension distincte

          Le statut dit où en est le traitement ; la décision dit si la réclamation est fondée. Un dossier « Réponse envoyée » peut être « Non fondé » ; un dossier « Clôturé » peut être « Partiellement fondé ». La décision est préparée dans la solution, approuvée, puis copiée sur le dossier à l'envoi de la réponse.

          Fondée Partiellement fondée Non fondée Irrecevable motivée

          Règles communes à toutes les transitions

          • Un motif écrit est obligatoire (sauf transitions automatiques).
          • Chaque transition crée un événement de chronologie et une entrée d'audit, jamais modifiés ni supprimés.
          • Aucun dossier déposé ne peut être supprimé par un profil métier : un doublon est marqué, pas effacé.
          • La réouverture crée un dossier enfant ; l'ancien dossier et sa réponse restent consultables.
          • Le client voit un statut simplifié, jamais le statut interne brut.

          Glossaire du pilotage

          Indicateurs : définitions et calculs

          Chaque indicateur de TSITA GEST affiche sa période, sa date de calcul et sa définition. Tous partagent les mêmes filtres : période, agence de réception, entité de traitement, nature, produit, canal, statut.

          Équipes IT

          Guide d'installation technique

          Mise en route locale de l'environnement de démonstration : API Laravel, application React et base MySQL. Environnement fictif, sans connexion aux systèmes BSCA.

          1. Prérequis

          PHP 8.3+avec extensions pdo_mysql, mbstring, openssl, intl, fileinfo, zip
          Composer 2gestionnaire de dépendances PHP
          Node.js 20+avec npm 10+ pour le front-end
          MySQL 8+127.0.0.1:3306 · utilisateur root sans mot de passe (local uniquement)

          2. Base de données

          Créez les deux bases (application et tests). Les scripts de référence se trouvent dans base-de-donnees/ (schema.sql, donnees-demo.sql, dictionnaire et MCD). En temps normal, les migrations Laravel suffisent.

          # Créer les bases (utf8mb4) mysql -u root -e "CREATE DATABASE tsita_gest CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;" mysql -u root -e "CREATE DATABASE tsita_gest_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;" # Variante sans Laravel : charger les scripts SQL fournis mysql -u root tsita_gest < base-de-donnees/schema.sql mysql -u root tsita_gest < base-de-donnees/donnees-demo.sql

          3. Back-end (API Laravel)

          1. Installer les dépendances
            cd backend composer install
          2. Configurer l'environnement — vérifier DB_DATABASE=tsita_gest, APP_TIMEZONE (stockage UTC, affichage Africa/Brazzaville), SANCTUM_STATEFUL_DOMAINS=localhost:5173,127.0.0.1:5173 et APP_DEMO_MODE=true.
            cp .env.example .env php artisan key:generate
          3. Créer le schéma et le jeu fictif (≈ 240 réclamations sur 12 mois, comptes de démonstration, règles de délai de démonstration, jours fériés CG 2025–2027).
            php artisan migrate --seed
          4. Lancer l'API — disponible sur http://127.0.0.1:8000/api/v1.
            php artisan serve --port=8000

          4. Front-end (React + Vite)

          1. Installer les dépendances
            cd frontend npm install
          2. Lancer le serveur de développement — Vite relaie /api et /sanctum vers http://127.0.0.1:8000 (même origine, cookies Sanctum).
            npm run dev
          3. Ouvrir l'application : http://localhost:5173
